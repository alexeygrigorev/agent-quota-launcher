# Host admission contract, draft v0.1

Owner: launcher design; integration implementation requires native launcher head and coordination head acknowledgement. This document does not claim that remote dispatch exists. As observed on 2026-10-04, the launcher implementation is local-only and under repair. SSH transport belongs to `agent-coordination`; quota, resource and task admission belongs to `agent-quota-launcher`. Neither side may infer healthy execution from transport success.

## Request and decision

The caller supplies a JSON request with `schema_version: 1`, a globally unique request ID, the stable task idempotency key, task ID, project ID, owner native identity, declared goal and acceptance evidence, required capabilities, timeout seconds, memory MiB, disk reservation bytes, write paths and target device ID. Device identity is an enrolled opaque ID, not a hostname supplied by an untrusted task. Owner identity includes device ID, canonical native workspace, native session ID and harness. Paths are absolute on the target device and validated there; a Windows path is never interpreted as a Linux path.

The transport resolves target device ID only through an operator-owned allowlist of SSH aliases. A remote advertised catalog lists supported adapter IDs, installed versions, declared model/task capabilities and catalog observation time. A request names a catalog adapter/model, never arbitrary shell text. SSH host identity must be verified by the configured known-host trust. Credentials stay with the target host and are never copied into requests, reports, prompts or repositories.

A read-only decision contains `decision_id`, `request_id`, `task_id`, `idempotency_key`, `project_id`, `device_id`, `workspace`, `evaluated_at`, `expires_at`, `policy_version`, `catalog_version`, `eligible`, `blocked_reasons`, normalized quota windows and resource observations. Every observation records its source and timestamp. Unknown quantities are null with reasons, never zero or fabricated capacity. The decision includes candidate adapter/model, weighted selection inputs and random draw provenance only after hard eligibility checks. A read-only decision is not a reservation or permission to launch later using cached quota.

Quota observations distinguish account identity aliases from independent capacity, actual remaining windows, reset instants, unknown/malformed windows, ordinary paid entitlement and promotion eligibility. Missing promotion proof removes the bonus; it does not remove independently verified ordinary paid eligibility. Route health is last actual model result with bounded age, or unknown. Task fit comes from explicit required capabilities and catalog support, not a constant called a measured score. Unsupported adapters are excluded before the random draw.

Resource observations include target boot identity, MemAvailable bytes, live and uncertain reservations, target filesystem identity/free bytes, owned scratch filesystem identity/free bytes and configured admission floors. Re-evaluate on the target under its local launch lock immediately before dispatch. The current policy requires worker memory at most 1500 MiB, at least 10 GiB available after relevant reservations and at least 50 GB plus 512 MiB headroom on both actual write and temporary mounts. If policy implements 50 GiB instead, report that stricter threshold explicitly.

## Dispatch and reconciliation

Only an explicit dispatch operation creates a durable target reservation and transitions the task. Store the intended adapter argv as structured fields, the stable request key, owner, scoped write paths and target identity before calling the native launcher. A timeout/disconnected response after submission is `launch-uncertain`, retaining duplicate suppression and appropriate reservations. A retry first queries the same target by stable request/task key and native session identity; it must not create a second writer merely because SSH returned no response.

The acknowledgement contains the native session ID, observed boot/process identity where available, native workspace, selected adapter/model, launch time, reservation and subsequent first-tool evidence. Do not treat the acknowledgement itself as agent first action. A genuine first action must match the assigned session and context and make useful progress on the declared task. A changed boot or PID requires reconciliation, not an assumed match. A completed process remains awaiting review until task evidence is checked; known-dead process memory can be released separately from write ownership or review state.

Report structured error classes: `unknown_device`, `transport_unavailable`, `catalog_stale`, `unsupported_adapter`, `quota_unknown`, `quota_exhausted`, `entitlement_unknown`, `route_unhealthy`, `task_unfit`, `memory_floor`, `disk_floor`, `path_conflict`, `duplicate_request`, `launch_uncertain`, `first_action_missing`, `timeout`, `result_rejected`. Include a safe evidence reference and next reconciliation time/condition where known. Never include credential-bearing raw command output.

## Local delivery boundary

For v0.1, remote requests return `unsupported_remote_dispatch` until a tested adapter implements this contract. The local CLI can expose the same projection with a fixed enrolled device ID, native workspace and real observations. Dashboard joins use `(device_id, project_id, task_id, native_session_id)` and usage event deduplication keys; unknown provider usage remains null. Existing collectors and services continue running. No second quota daemon, fake historical 24-hour series, or copied provider credentials are required.

Integration acceptance must include an allowlisted read-only catalog request; an unknown-device rejection; one genuine task on the target with first tool and result evidence; a lost acknowledgement reconciliation that creates no duplicate writer; and completion admitting a distinct ready task with fresh quotas and resources. These tests are requirements, not evidence already obtained.
